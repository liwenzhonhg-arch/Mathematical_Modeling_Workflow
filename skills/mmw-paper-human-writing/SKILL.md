# 数学建模论文自然表达

运行环境：Python 3.10+；审计脚本仅使用标准库。

## 目标

让读者能够沿着材料、模型、计算和结论复原作者的思路。论文的“人味”来自选择了什么
证据、怎样组织论证、在哪里收住结论，不来自口头禅、个人故事、故意犯错或随意插话。

同时满足三个目标：

1. **可信**：公式、数值、单位、引用和方法边界可追溯。
2. **清楚**：每段承担明确任务，读者知道这段为什么出现在这里。
3. **自然**：句子服从论证关系，不服从统一模板和固定鼓点。

## 先判断任务

- 新写或大幅重写整篇论文：读取 `references/section-contracts.md` 和
  `references/protected-content.md`。
- 修改已有章节：读取对应章节合同，再读取 `references/revision-checklist.md`。
- 只检查文风：运行 `scripts/audit_latex_prose.py audit <文件>`，按 warning 回到原文判断。
- 检查摘要覆盖：在有 analyze 完成契约时，运行 `audit <文件> --expectations <contract.json>`；
  覆盖报告只提供任务、方法和结果证据线索，不把缺少字符串判成问题未解决。
- 对文件实施改写：改写前读取 `references/protected-content.md`；完成后必须运行
  `compare`。

不要一次加载与当前章节无关的所有资料。

## 第二版篇章合同

本 Skill 已按真实竞赛论文样本校准，但不复制任何原文，也不把词频当作“人味”指标。写作前
在内部建立“任务—证据—判断—边界”账本：

- 摘要按 analyze 的规范子问题逐题覆盖实际方法与核心结果；
- 问题分析把题目翻译成决策变量、状态、目标、约束、输出和方法理由；
- 主要公式附近形成“目的—关系—关键项—实现—结果”的局部闭环；
- 结果段遵循“证据—观察—机制—边界”，先定位图表或指标，再解释现象和决策范围；
- 评价写“设计选择—能力—证据”与“缺失机制/数据—影响—推广条件”。

审计器按章节边界分别检查顺序词、证据窗口、段首和近重复；不同章节的合法表达不应互相累计。
`本文`、`我们`、`首先`、`其次`、`建立`、`得到`、`可以看出`等词按语义使用，不是禁词。真实
顺序、列表、冒号、破折号和必要对比可以保留；没有证据的抬价、重复总结和同义改写式注水才是
优先修改对象。不要为了躲避 AI 检测器追求固定词频、句长或概率分数。

## 第一性原理

### 句子为什么存在

论文中的句子至少完成一项工作：定义对象、说明条件、建立关系、报告结果、解释机制、
比较方案、限定结论或承认局限。找不到工作内容的句子通常只是姿态，应删除或补上证据。

### 段落怎样推进

每段只承担一个主要任务，并增加新的定义、条件、公式解释、数据、比较、机制或局限。
同一结论换词再说一次不算推进。后一段应接住前文留下的真实问题，不靠“更深层次”制造
虚假层级。

### 作者怎样出现

作者性体现在方法选择和判断边界中。例如说明为何采用这一误差口径、为何保留某项约束、
当前证据只支持哪一级结论。不要用个人经历、情绪或频繁的“我们认为”制造存在感。

## 写作流程

### 1. 冻结证据

先列出本节允许使用的输入：题面事实、数据摘要、方法合同、结构化结果、图表 manifest、
参考文献和已声明局限。材料不足时缩小结论或返回上游补证据，不用套话补篇幅。

已有文件改稿时，先运行：

```powershell
python scripts/audit_latex_prose.py audit sections/model_solution.tex
```

审计结果只提供线索，不替代阅读。

### 2. 确定章节任务

从 `references/section-contracts.md` 读取当前章节合同。问题重述、模型推导、结果解释和
模型评价承担不同任务，不能共用一套“背景—方法—意义”模板。

### 3. 建立段落账本

在内部为每段记录：

- 这段回答什么问题；
- 使用哪项公式、数据、图表或条件；
- 得出什么判断；
- 判断到哪里为止；
- 下一段为什么必须接着出现。

不要把账本原样写进论文。

### 4. 直接写论证

- 定义先给对象和含义，再给符号或公式。
- 方法选择先写任务需要，再写模型如何满足需要。
- 结果段先给最关键的比较，再解释原因或影响。
- 局限写清缺失机制会影响什么，避免礼貌性自我批评。
- 主动与被动句式按信息焦点选择。需要承担选择责任时写清主体；过程或对象更重要时可用
  无主句或被动结构。
- 真实分类可以列表，定义可以用冒号，必要区别可以使用对比句。标点和句式服从语义，
  不服从禁词清单。

### 5. 分层改稿

按顺序执行，不能先润色再核事实：

1. **保真**：核公式、数值、单位、引用、图表和方法边界。
2. **论证**：核每段任务、证据和结论是否匹配。
3. **压缩**：删除重述、机械总结和不增加信息的过渡。
4. **中文**：调整主干、指代、停顿和术语一致性。
5. **冷读**：找出最像“模型在完成写作任务”的段落，说明它缺的是材料还是组织。

详细检查见 `references/revision-checklist.md`。

### 6. 验证受保护内容

把改稿保存到新文件或受控临时文件，再运行：

```powershell
python scripts/audit_latex_prose.py compare before.tex after.tex
python scripts/audit_latex_prose.py audit after.tex
```

`compare` 失败表示公式、数值、引用、URL、单位或 MMW 追踪信息发生变化。除非用户明确
要求修改相应事实或模型，否则必须恢复。文风 warning 要回到语境判断，不能为清零统计而
改坏论文。

## 绝对边界

- 不新增结构化结果中没有的数值、百分比、倍数、阈值或精度。
- 不把 heuristic、有限枚举或多起点局部结果写成无条件最优。
- 不改变公式、变量含义、单位、引用归属或图表对应关系来换取顺畅。
- 不编造研究过程、失败经历、人工决策、现场观察或团队主观感受。
- 不把“本文”“因此”“同时”等词机械清零；只处理过密、空转或错误连接。
- 不以 AI 检测器分数为目标。检查器只能定位重复形状，不能证明作者身份。
- 不强制图表后写固定行数。只写读图不能直接得到的比较、机制、影响和边界。
- 不新增顶层工作流阶段；在 MMW 中只作为 `paper` 阶段内的受约束编辑能力。

## 交付

用户只要文本时，交付改好的文本。用户要求修改文件时，报告：

- 修改了哪些文件或章节；
- `compare` 是否通过；
- `audit` 仍有哪些需要人工判断的 warning；
- 哪些内容因证据不足保持原样或返回上游。

不要声称“已去除全部 AI 痕迹”。应说明具体减少了哪些模板、重复和无证据表述。
