# mmw 三题盲测汇总报告

## 结论

当前版本不能独立产出可信的国赛提交物。三题的分析、EDA 和建模框架都有可用片段，但 3/3 在代码阶段失败，3/3 求解结果为空，3/3 仍被允许生成论文、审批、编译和导出。系统最危险的缺陷不是某个 Agent 能力不足，而是已发现的错误不会阻断下游。

## 共性失败链

1. `analyze` 能拆题，但硬交付物提取没有题面证据约束，2/3 题出现文件名幻觉。
2. `eda` 能生成图，却缺少按题型的数据语义校验；合并单元格、编码和时间区间统计均出现错误。
3. `model` 与 `verify` 能写出正确风险提示，但 verify 报告不参与状态流转。
4. `code` 三题全部失败，反思循环没有稳定修复数据索引、依赖版本和输出包裹问题。
5. `solve` 把运行失败保存为 completed，并把旧图当成本次求解图表。
6. `paper` 明知 `results.json` 为空、`needs_upstream_data=true`，仍生成含具体数值的论文。
7. `review` 已准确发现大部分致命问题，但 fail 项不阻止审批。
8. `export` 在硬交付物缺失时只打印警告，仍以成功状态生成 zip。

## 最大遗漏

项目把“产出一份报告”和“通过质量检查”混为一件事。Verifier、摘要评分器、数值审计器和 Reviewer 已经产生足够多的失败证据，但状态机没有统一的硬门禁。因此继续优化提示词或增加 Agent，只会提高错误成品的可读性，不会提高可信度。

## 最小修复顺序

1. **先修统一失败语义**：`code`/`solve` 非零退出、必需 JSON 缺失或为空时不得 completed。
2. **再加论文门禁**：`results.json` 为空、`needs_upstream_data=true` 或数值审计超阈值时不得进入/通过 paper。
3. **最后修导出门禁**：题面明确要求的交付物缺失时 `export` 返回非零，不生成提交包。
4. 门禁稳定后，再分别修 EDA 语义、Coder 反思和 Reviewer artifact 格式。

前三项都应复用现有执行结果、artifact 和审计数据，不需要增加 Agent、框架或新依赖。

| 题目 | 新工作区停止位置 | 阻断原因 | 是否产生伪提交包 |
|---|---|---|---|
| 2021B | model 审批 | Verifier `block`：收率公式量纲错误 | 否 |
| 2020A | code 运行 | Coder Key 认证失败，立即非零退出 | 否 |
| 2018A | model 审批 | Verifier `block`：皮肤边界/观测位置错误 | 否 |

补充正常路径回归：已有 2023B 的 code、solve、paper 均通过质量复核；重新生成 review v15 后，结构化 checklist 与数值审计通过，`export` 成功。修复后的关键变化是：错误题如实停止，已有可信结果仍能导出。

### 自动修订迭代

- 2018A：model v1 block 经一次定向修订形成 v2，Verifier 变为 pass。
- 2021B：重新建模 v2 首次验证不再 block，可正常审批。
- 2020A：`check-config` 提前发现 Coder HTTP 401；未修改用户 Key。
- 2020A 的 model 自动修订最终推进到 v5 warning 并激活；固定温区未再被建议改成决策变量。
- 三道盲测目前都已通过 model 门禁；完整 code/solve 回归共同等待 Coder Key 修复。
- Coder Key 修复后已继续实跑：三题都进入 code，但分别因奇异矩阵、未定义变量、solution 尾部 Markdown 说明而失败；三者均被 code 审批门禁阻断，没有传播到 solve/paper。
- Coder 第二轮修复后，2021B 已推进到 review（因不合理外推和数值审计 fail 被阻断）；2020A 转为计算超时；2018A 转为 Excel 表头识别错误。系统仍没有把失败包装成提交物。
- 完整自动化基线增至 158 passed，2023B export 继续成功。
