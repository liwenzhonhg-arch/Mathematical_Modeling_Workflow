## 1. 改进目标

修复首次实地审核暴露的两个根因，并补齐尚未执行的验证闭环：

1. 摘要覆盖检查只匹配 canonical ID 和结果变量名，无法识别自然语言任务对象、结果别名及
   “数值 + 单位”表达，产生系统性假阴性；
2. 顺序词、证据和段首检查没有可靠的章节边界，可能把不同章节中的合法表达聚合成模板 warning；
3. 当前只有确定性审计，没有同输入的首版/第二版 A/B 输出、人工盲评和端到端回归证据。

改进后，审计器只回答它能确定的问题：保护内容是否变化、期望项是否有可定位证据、哪些段落
需要人工复核。它不得用字符串缺失直接判定论文没有解决某个问题，也不得把 warning 数量下降
当作 Skill 有效的充分证据。

## 4. 摘要覆盖检查改进

### 4.1 新期望契约

覆盖检查接受以下 evaluator-only JSON：

```json
{
  "subproblems": [
    {
      "id": "q1",
      "title": "司机决策模型",
      "aliases": ["排队等待与空载返回", "司机收益决策"],
      "method_terms": ["期望收益", "随机决策模型", "蒙特卡洛"],
      "results": [
        {
          "name": "q1_base_queue_profit",
          "aliases": ["排队等待预期收益"],
          "value": 2.1838753353,
          "display_values": ["2.18"],
          "unit": "元"
        }
      ]
    }
  ]
}
```

字段规则：

- `id`、`title` 必填；
- `aliases`、`method_terms`、`results` 可为空，但必须由 analyze、method contract 或
  `results.json` 生成，不由审计器猜测；
- `display_values` 由结构化结果按论文声明的精度预先生成，审计器不得自行改变舍入规则；
- 同一数值若对应多个结果，必须同时匹配单位、任务对象或结果别名，不能仅凭数字认领；
- 契约中不得包含模型答案范围、隐藏 Oracle 或人工臆测的预期结论。

### 4.2 三路证据匹配

每个子问题分别报告：

1. **任务证据**：规范 ID、标题或显式别名；
2. **方法证据**：实际 method contract 中的方法词或预声明别名；
3. **结果证据**：结果名、结果别名，或与单位和任务对象共同出现的批准显示值。

输出不能只有布尔值，必须记录：

```json
{
  "id": "q1",
  "task_present": true,
  "method_present": true,
  "result_present": true,
  "evidence": [
    {"kind": "task_alias", "text": "排队等待与空载返回", "line": 3},
    {"kind": "method_term", "text": "随机决策模型", "line": 3},
    {"kind": "result_value", "text": "2.18元", "line": 4}
  ]
}
```

没有匹配时输出 `missing_evidence`，不输出“该问题未解决”。覆盖报告是人工复核线索；只有摘要
合同明确要求且期望契约完整时，流水线门禁才能据此失败。

### 4.3 防误匹配

- 区分 `q1` 与普通单词、公式下标或引用键；
- 数值必须匹配完整 token，不允许 `2.1` 命中 `12.18`；
- 百分比、正负号、科学计数法和单位必须一致；
- 相同数值出现在多个子问题时，不自动归属；
- 任务别名只允许规范化空白和全半角，不做任意模糊匹配；
- 方法词命中参考文献或目录时不计入摘要覆盖。

## 5. 章节感知审计

### 5.1 章节切分

使用标准库按输入格式切分：

- LaTeX：`\\section`、`\\subsection`、`\\subsubsection`；
- Markdown：`#`、`##`、`###`；
- 纯文本：空行分段，不猜测章节名称。

切分必须保留原文件字符偏移和行号。公式、注释、表格、代码和机器字段继续沿用现有屏蔽逻辑。

### 5.2 顺序词

`sequence_template` 仅在以下情况提醒：

- 同一章节或同一段内出现完整顺序词序列，但附近没有可识别研究动作或真实依赖；
- 两个以上章节重复使用相同的完整段落模板，而不只是都出现“首先”；
- 顺序词后的句子只是目录性描述，没有变量、方法、数据、动作或输出。

不同章节分别使用“首先”不得合并报警。摘要按多个问题组织时，顺序词与实际任务、方法和结果
绑定即视为合法。

### 5.3 证据窗口

`result_evidence_chain` 的证据窗口限制在：

- 当前句；
- 同一段的前一句；
- 同一章节内紧邻的图表引用或公式。

不得跨章节借用数字或图表，也不得因为上一节出现过数字就放过当前空泛结论。匹配到证据只表示
“附近存在材料”，不能自动证明因果解释正确。

### 5.4 段首与评价

- `问题一`、`针对问题二`、`对于问题三` 等任务定位语不计入重复段首；
- 相同标题下连续使用“本问题旨在”或“分析结果显示”三次以上才提醒；
- 评价具体性同时检查模型对象、设计选择、证据或数据条件，单独出现“模型”不能解除 warning；
- 推广只有在出现新增数据、变量映射、约束变化或重校准条件时才视为具体。

## 6. A/B 实地评测闭环

### 6.1 冻结基线

在修改 Skill 前复制首版 Skill 到 evaluator-only 快照目录。快照只用于评测，不覆盖现役 Skill，
不进入发行物。

每个评测片段生成：

- `source`：原文；
- `baseline`：首版 Skill 输出；
- `candidate`：改进后 Skill 输出。

三组使用相同模型、温度、上游材料和方法合同。随机模型各运行 3 次，并记录 token、时长和失败。

### 6.2 盲评

版本标签随机改为 A/B/C，至少 2 名评审独立评分：

- 信息推进；
- 逻辑清晰；
- 模板感；
- 学术克制；
- 保真度；
- 最终提交偏好。

评分完成前不得解盲。自动审计 warning 数量只作旁证，不进入人工偏好分数。

### 6.3 最低通过标准

- 保护内容通过率 100%；
- 摘要任务—方法—结果覆盖不下降；
- candidate 的信息推进、逻辑清晰平均分至少比 baseline 高 0.3；
- candidate 的模板感平均分至少下降 0.5；
- candidate 的盲选率不低于 60%；
- 合格正例被无必要改写的比例不超过 20%；
- 无严重事实、公式、数值、方法证书或结论边界错误。

样本或评审人数不足时标记 `insufficient_sample`，不能标记 `verified`。

## 7. 端到端回归

从已批准的 solve 检查点复制一个隔离工作区，只运行：

```text
paper -> review -> compile
```

验证：

- 原工作区和现役版本哈希不变；
- 新论文的 LaTeX、Markdown 和 PDF 可对应追溯；
- 数值审计、方法追踪、benchmark 和 PDF 视觉门禁通过；
- Reviewer 没有因为语言变顺而漏报模型、数据或结果问题；
- `compare` 对授权范围外的公式、数值、引用和 MMW 注释变化继续阻断。

禁止在原工作区直接重跑 paper 作为 A/B 试验。

## 8. 测试合同

至少新增以下回归测试：

1. 标题或别名出现时，任务覆盖通过；
2. 结果名未出现，但批准显示值、单位和任务对象共同出现时，结果覆盖通过；
3. 相同数值但单位或任务对象不符时，不得误匹配；
4. `q1` 出现在引用键、公式或代码中时，不计入任务覆盖；
5. 不同章节各出现一次“首先”时，不产生 `sequence_template`；
6. 同一章节重复完整空模板时，产生 warning；
7. 图表证据不能跨章节消除 `result_evidence_chain`；
8. 合格摘要、结果段和评价段保持无过度改写；
9. 现有 compare、公式屏蔽、引用屏蔽和退出码测试继续通过；
10. 对首次审核论文只读回归，原文件哈希保持不变。

1. 冻结首版 Skill 和 10 个分层测试片段；

8. 生成审核报告，再决定是否标记 `verified`。
