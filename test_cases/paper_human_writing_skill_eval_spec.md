# 数学建模论文自然表达 Skill 检验规格

状态：草案，待确认

## 1. 目的

验证 `mmw-paper-human-writing` 是否在真实论文中减少模板化表达，同时保持数学内容、数值结果、
方法声明和结论边界不变。

本规格检验的是“能否稳定改善论证表达”，不是检测器分数、词频或句长变化。2019 年论文展示语料
只用于校准写作合同，不直接作为最终效果测试集，也不作为模型正确性的 Oracle。

## 2. 被测对象与对照组

### 2.1 被测版本

- Skill：`skills/mmw-paper-human-writing/`；
- Writer、Reviewer、Abstract Critic 的当前提示词；
- `scripts/audit_latex_prose.py` 的当前审计规则。

### 2.2 对照组

至少保留一组可复现对照：

1. **原文组**：不经过改写，仅做格式规范化；
2. **首版组**：使用改造前的 Skill 或冻结的首版输出；
3. **第二版组**：使用当前 Skill。

若无法恢复首版 Skill，使用原文组作为最低对照，并在报告中标记 `baseline_missing`，不得把第二版
与原文的差异全部归因于 Skill。

## 3. 测试材料

### 3.1 分层组成

最终测试集至少包含 10 个脱敏片段，每类 2 个：

| 类别 | 片段内容 |
|---|---|
| 摘要 | 至少两个顶层子问题，包含方法与结构化结果 |
| 问题分析 | 题面复述与变量、约束、输出、方法理由混合的片段 |
| 模型说明 | 至少一个公式及其前后解释 |
| 结果分析 | 图表、数字、比较和结论边界 |
| 模型评价 | 优点、局限和推广条件 |

每类必须同时包含：

- 一个确实需要改写的负例；
- 一个已经合格、不得为了制造变化而改写的正例。

### 3.2 训练/校准集与测试集隔离

- Skill 评测样例可以使用合成片段；
- 真实论文测试片段不得提前写入 Skill、Writer prompt 或示例输出；
- 真实论文全文和工作区状态保存在 Skill 目录之外；
- 原论文、`.mmw/`、`output/` 和现役版本只读，不作为改稿输出目录。

### 3.3 输入冻结

每次实验记录：

- 输入文件 SHA-256；
- 使用的 Skill 版本和 Git commit（若有）；
- 模型、温度、随机种子或供应商 usage；
- Writer prompt、上游结构化结果和方法合同的版本；
- 运行时间和失败原因。

同一 A/B 组不得更换输入材料、结果文件或方法合同。

## 4. 检验层级

### 4.1 L0：结构和资源检查

检查：

- `SKILL.md` frontmatter 可解析且少于 500 行；
- `references/`、`scripts/`、`evals/` 路径存在；
- eval JSON 合法，所有 fixture 可读取；
- Skill 不包含真实论文全文、机器绝对路径、密钥或运行时 OCR 依赖。

L0 任一失败即停止，不进入文本效果评估。

### 4.2 L1：确定性保真检查

对每个改写结果运行：

```powershell
python skills/mmw-paper-human-writing/scripts/audit_latex_prose.py compare before.tex after.tex
python skills/mmw-paper-human-writing/scripts/audit_latex_prose.py audit after.tex
```

必须保持：

- 公式、数学环境和变量名；
- 数值、单位、百分号、区间和科学计数法；
- `\\cite`、`\\ref`、`\\label`、URL 和图表引用；
- `% MMW-ALGORITHM:`、`% MMW-ID:`、`% MMW-LIMITATION:`；
- 方法合同中的算法类别、目标、约束、近似和证书等级。

L1 的保护内容通过率必须为 100%。任何一例失败均为 `fail`，不得用人工“看起来没问题”覆盖。

### 4.3 L2：结构化覆盖检查

摘要使用 analyze 完成契约 JSON 检查：

- 每个规范子问题 ID 是否出现或有明确任务对象；
- 每个子问题是否出现实际方法；
- 每个子问题是否出现结构化结果名或对应核心结果；
- 覆盖率不得低于原文或首版组。

结果分析和模型评价分别检查：

- 是否存在证据定位、观察、机制、决策边界；
- 是否把优点写成“设计选择—能力—证据”；
- 是否把局限写成“缺失机制/数据—影响—受影响结论”；
- 推广是否说明新增数据、变量、约束或重校准条件。

L2 只判断结构线索，不自动判定数学推理正确性。

### 4.4 L3：盲评 A/B

每个片段生成原文/首版/第二版结果，随机化标签后交给至少 2 名评审。评审不得看到版本来源。

每个片段按 1--5 分评分：

1. 信息推进：是否增加定义、证据、机制、比较或边界；
2. 逻辑清晰：能否复原任务—证据—判断；
3. 模板感：是否存在固定路标、重复段首或同义改写式注水；
4. 学术克制：是否出现无证据抬价、过度归因或超范围结论；
5. 阅读偏好：若只能提交一个版本，选择哪个。

“模板感”分数越低越好，其余分数越高越好。评审意见必须指出具体句子，不能只填总分。

### 4.5 L4：端到端回归

在工作区副本运行：

```text
paper -> review -> compile
```

检查：

- LaTeX 编译和 PDF 视觉门禁；
- 数值审计、方法追踪和结果哈希；
- Reviewer 是否仍能识别原有问题；
- 是否出现“更顺但改变含义”的改写；
- 论文正文、Markdown、PDF 的结构化内容是否一致。

L4 不要求新版 warning 数量必然更少；删除一个 warning 若同时损失证据或边界，视为回归。

## 5. 通过标准

### 5.1 硬门禁

以下条件必须全部满足：

- L0、L1、L4 全部通过；
- 保护内容通过率 100%；
- 不新增结构化结果不存在的数字、结论或方法证书；
- 摘要子问题方法—结果覆盖率不下降；
- 不修改原论文、`.mmw/`、`output/` 或现役版本。

### 5.2 效果门槛

首轮试验使用以下最低门槛，后续可根据样本量修订：

- 第二版在“信息推进”和“逻辑清晰”平均分上不低于首版，且至少高 0.3 分；
- 第二版在“模板感”平均分上至少下降 0.5 分；
- 盲评中第二版被选为更佳版本的比例不低于 60%；
- 正例片段被无必要改写的比例不超过 20%；
- 任一片段不得出现严重事实、数值、公式或结论边界错误。

若样本不足以稳定估计均值，报告 `insufficient_sample`，不得宣布 Skill 已验证。

## 6. 失败分类与回路

| 失败类型 | 回到哪里 |
|---|---|
| 公式、数字、引用被改动 | Skill 的保护合同、`compare` 或 Writer prompt |
| 缺少方法、结果或上游数据 | `analyze`/`solve`，不是继续润色 |
| 逻辑链断裂、机制解释错误 | `paper` 内容合同，必要时回到 `model` |
| 评价仍是通用形容词 | Writer/Reviewer 的评价具体性规则 |
| 合格正例被过度改写 | 增加保留性反例和停止改写条件 |
| 文字更自然但结论变强 | 方法合同、数值门禁和结论边界 |

每轮只修复一个主要失败类型，禁止同时改变 Skill、模型、数据和评测集。

## 7. 评测产物

确定性 A/B 门禁使用项目工具：

```powershell
python tools/evaluate_paper_human_writing.py `
  --source <source.tex-or-dir> `
  --baseline <baseline.tex-or-dir> `
  --candidate <candidate.tex-or-dir> `
  --output <evaluator-only-output> `
  --expectations <analyze-completion.json>
```

该工具只比较和审计已提供的三组文本，不生成改稿，也不代替盲评。

每次评测生成一个不进入 Skill 的结果目录，至少包含：

```text
manifest.json              # 版本、输入哈希、模型和运行参数
baseline/                   # 原文或首版输出
candidate/                  # 第二版输出
deterministic/              # compare、audit、coverage 结果
blind_scores.csv            # 去除版本标签后的人工评分
failure_log.md              # 逐片段失败原因和回路
report.md                   # 通过/失败/样本不足结论
```

`report.md` 必须分别报告：

- `verified-current`：已由当前测试证实；
- `pending`：材料或人工评审不足；
- `out-of-scope`：本轮未检验的能力；
- 删除候选或临时残留。

## 8. 重复性与停止条件

- 随机模型至少重复 3 次；若供应商不支持固定种子，记录 usage 并报告方差；
- 新增评测样例必须加入冻结清单后才能进入下一轮；
- 连续两轮硬门禁通过且效果门槛通过，才可称为“当前测试集 verified”；
- 不得据此宣称 Skill 能识别作者身份、消除全部 AI 痕迹或适用于所有论文。

## 9. 边界

- 评测不训练分类器、不微调模型、不建立 AI 检测器；
- 不把 2019 论文原文复制进 Skill 或公开评测结果；
- 不用词频、句长变异系数或某个检测器分数作为单独通过依据；
- 不因“本文、我们、首先、建立、得到、可以看出”等词出现就判定失败；
- 不删除临时结果、缓存或原始材料，除非用户在评测报告后单独确认清理。
