# 外部数模 Agent 可学习项 Spec

状态：L1、L2、L3 安全清单与 L4 已实现；L3 自动解释待供应商能力接入
制定日期：2026-08-06
来源：小红书笔记《狂烧70亿token后关于数模agent的一些反思》及其公开流程图、评论区复盘。

## 1. 目标

只吸收能够提高真实题目完成率的机制，不复制其 Agent 数量、候选数量和重复评分规模。MMW 继续保持固定八阶段，不新增顶层阶段。

## 2. 可学习机制

### L1：有上限的方法候选计划

- 每个题面顶层子问题最多保留 3 个候选：1 个基线、最多 2 个增强方案。
- 每个候选必须声明所需数据、关键假设、预计复杂度、失败条件和廉价试跑规则。
- 候选数量不足不自动补齐；候选超过上限时确定性拒绝，不能让 LLM 无限扩展。
- 只有经过证据筛选的候选才能进入 Modeler，不能用“多个 Agent 都同意”代替证据。

产物：`method_candidates.json`。

### L2：证据化文献检索

- 从 Researcher 已明确标记的 `[需要搜索: ...]` 生成有限查询，不额外让 LLM 发散关键词。
- 只访问固定的学术元数据端点；首版使用 OpenAlex 与 Crossref。
- 每个查询每个来源最多返回 3 条，总查询数最多 4 条。
- 按 DOI、OpenAlex ID、规范化标题去重，保存题名、作者、年份、DOI、来源地址、摘要片段和检索来源。
- 元数据或摘要只能支持“候选资料”判断；没有全文时不得伪装成已核验全文结论。
- 网络失败不得伪造结果；保留错误类型和未解决查询，继续使用本地 HMML/人工资料。
- 默认关闭，由用户显式配置开启，避免题目内容被无提示发送到外部服务。

产物：扩展后的 `research_evidence.json`。

### L3：通用视觉证据清单

- 初始化项目时，从 DOCX/PDF 中安全提取可用的嵌入图片或页面图像引用，原题文件保持不变。
- 每项记录来源文件、页码或文档部件、SHA-256、MIME、尺寸以及是否已机器解释。
- 视觉模型输出必须绑定证据项 ID，并给出结构化结论和置信度；低置信度只形成有限候选或人工检查项。
- 不把 OCR/视觉猜测混同为原文证据；DOCX 原生 shape 定位文本继续标为 `native-shape-text`。
- 首版先建立安全清单和未解析状态；只有供应商明确支持图像输入时才启用自动解释。

产物：`.mmw/input_evidence.json` 与受控缓存目录 `.mmw/cache/problem-assets/`。

### L4：廉价方法试跑

- 位于 `model -> code` 的阶段内部，不新增顶层阶段。
- 对获选模型先运行缩小规模、低精度或合成不变量检查，最长 30 秒。
- 试跑只判断代码路径、数据可读性、有限输出、约束方向和数量级，不宣称最终精度或最优性。
- 试跑失败时携带确定性错误返回当前模型/代码修订；不得直接进入 300 秒正式运行。
- research 合同必须给出可执行的廉价检查；不能构造时不得把该候选送入 code。

产物：code 检查点中的 `method_pilot.json`；执行摘要复用 `attempt_history.json`。

## 3. 明确不学习的做法

- 不为同一职责增加多个同源 Reviewer。
- 不对每个子问题生成 6 个以上方案。
- 不通过反复 LLM 打分宣称结果真实。
- 不让不同 Agent 重复读取完整题目和全部历史。
- 不以 Token 消耗规模作为完成度或质量指标。
- 不降低现有独立 Oracle、数值出处审计、方法契约和 PDF 视觉门禁。

## 4. 实施顺序

1. 先完成 `workflow_efficiency_improvement_spec.md`，降低现有无效调用。
2. 实施 L1，形成有上限的候选合同。
3. 实施 L2，增加可选的学术元数据证据。
4. 实施 L3 的安全证据清单；视觉自动解释后置。
5. 已用独立真实题验证 L1 能稳定给出试跑规则，再实施 L4。

## 5. 验收标准

- 固定八阶段和现有检查点兼容。
- 默认离线运行行为不变。
- 未开启联网时 `external_search_performed=false`。
- 网络失败不导致已有离线 research 阶段损坏。
- 候选数量、查询数量、响应体积和缓存体积均有确定性上限。
- 任何“已验证”声明仍只能来自真实执行、独立 benchmark 或现有质量门禁。
