# 数学建模论文自然表达 Skill Spec

状态：首版已实现；第二版语料增强规格已确认并实现

## 目标

建立一个可独立复制的中文数学建模论文写作与改稿 Skill。它要减少模板化、空泛和
机械重复，同时守住论文比“像人说话”更重要的边界：公式正确、数值可追溯、术语
一致、引用完整、方法声明不过界。

“自然表达”不等于口语化、插入个人经历、故意制造错别字或随机打乱句长。论文中的
作者性来自材料选择、论证顺序、判断依据和边界意识。

## 目录合同

- Skill 固定放在 `skills/mmw-paper-human-writing/`。
- `SKILL.md` 是入口，只保留工作流、硬边界和按需读取路由。
- `references/` 保存章节合同、受保护内容和改稿检查表。
- `scripts/audit_latex_prose.py` 是标准库实现的只读审计器，不自动改文。
- `evals/evals.json` 保存可复用评测题，不保存模型运行结果。
- 临时输出进入仓库既有 `.tmp/` 或系统临时目录；不得把真实赛题答案复制进 Skill。

## 写作合同

1. 每段承担一个主要论证任务，并至少增加一项新的定义、条件、公式解释、数据、比较、
   机制或局限；换词重复不算推进。
2. 问题重述、问题分析、模型建立、求解结果、灵敏度和评价使用各自的章节合同，不用
   同一套“首先—其次—最后”覆盖全文。
3. 主动与被动句式按信息焦点选择；不规定“被动语态为主”，不以“本文”作为机械主语。
4. 冒号、破折号、必要对比、真实枚举和专业术语按语义使用，不设脱离语境的绝对禁令。
5. 图表后的文字只解释读图无法直接得到的比较、原因、影响或边界，不强制固定行数。
6. 不用“值得注意的是”“具有重要意义”等元话语替代证据；评价必须落到具体能力、
   代价、适用条件或失败方式。
7. 风格审计只产生 warning；公式、数值、单位、引用、标签和 MMW 追踪信息变化才属于
   阻断性问题。

## 受保护内容

改稿前后必须保持以下内容，除非用户明确要求修改相应事实或模型：

- LaTeX 数学片段和数学环境；
- 所有数值及其符号、百分号和科学计数法；
- `\cite`、`\ref`、`\label`、URL 和图表引用；
- `% MMW-ALGORITHM:`、`% MMW-ID:`、`% MMW-LIMITATION:`；
- 单位、变量名、结果等级和不确定性边界；
- `results.json`、`sensitivity.json`、`params.json` 与方法合同绑定的结论。

审计器的 `compare` 子命令必须检测数学片段、数值、引用/标签、URL 和 MMW 追踪注释的
增删改。比较失败时不得把改稿标记为完成。

## 审计器合同

- 支持 UTF-8 `.tex`、Markdown 和纯文本。
- 提取正文前屏蔽注释、公式、代码、URL 目标和机器字段，保留源文件行号。
- 不因冒号、破折号、“不是……而是……”或三项枚举本身报警。
- 检查空洞路标、机械顺序词、泛化评价、弱动词名词化、连接词过密、重复段首、
  近重复句和无数值/引用支撑的效果形容词。
- 文风 warning 的退出码为 0；读取错误为 2；受保护内容比较失败为 1。
- 文风统计只用于定位，不得优化成“躲过检测器”的文本。

## 工作流接入

- Writer 的系统提示采用本 Spec 的章节分工与表达边界，删除会主动制造模板腔的规则。
- Reviewer 的语言维度同时检查信息推进、段落重复、机械路标和空泛评价，不能只检查
  是否口语化。
- 本 Skill 是可复用编辑工具，不增加第九个顶层阶段；若以后自动调用，只能作为
  `paper` 阶段内的受约束编辑步骤。

## 验收

- Skill 目录结构和 YAML frontmatter 可解析。
- 审计器能忽略公式、引用、标签、URL、表格环境和 MMW 注释中的标点。
- 审计器能定位代表性的模板路标、泛化评价、名词化和近重复句。
- `compare` 对纯措辞调整通过，对数值、公式、引用或 MMW ID 变化失败。
- Writer 和 Reviewer 提示词包含本 Spec 的关键边界。
- 使用真实已交付论文只读审计时不得修改该论文或其 `.mmw/` 状态。

## 来源边界

本 Skill 受 `KKKKhazix/human-writing` 的“材料优先、逐段推进、事实与推断分离、成稿后
再审查”启发。原项目采用 MIT License。数学建模专用合同、LaTeX 保护机制、章节路由和
审计实现均按本项目需求重新设计；不继承原项目对冒号、破折号、对比句和排比的绝对禁令。

## 第二版：2019 论文展示语料增强

### 目标

第二版不训练新的语言模型，也不让 Skill 记忆或复述论文原文。它用一批生成式 AI 普及前的
真实竞赛论文校准写作合同，学习作者如何把题目要求转成模型、如何让公式与文字衔接、如何
从图表走到判断。最终仍以第一性原理裁决规则：表达必须帮助读者复原任务、证据、推理和结论
边界；语料中的高频写法若不能完成这个目标，就不进入 Skill。

### 语料范围与证据等级

只读语料为用户提供的“2019全国大学生数学建模竞赛论文展示”本地目录。它只用于本轮离线
分析，不是运行依赖；其机器绝对路径不得写入 Skill、发行物或测试快照。

本轮盘点得到 17 篇论文，覆盖 A 题 3 篇、B 题 3 篇、C 题 3 篇、D 题 4 篇、E 题 4 篇，
共 559 个正文图片页。Windows 中文 OCR 全量完成且无页面失败，得到约 191247 个可识别汉字。
宣传图片和非数字文件名资源未进入正文语料。OCR 文本与统计产物只保存在系统临时目录，
不得复制进 Skill 或提交到仓库。

证据分三级使用：

1. **全量统计证据**：用于判断某种词和句式是否普遍存在，不能证明具体一句话正确。
2. **分章节文本证据**：覆盖 17 篇摘要，并定位问题分析、模型建立、结果分析和模型评价页面，
   用于提取篇章动作。
3. **原页视觉核验**：按 A--E 五类题目抽查摘要、问题分析、图表解释和模型评价页面，用于
   排除 OCR 丢段、公式误识别和列表结构误判。

图片分辨率约为 826×1169，OCR 对普通中文段落可用，但对公式、上下标、编号、英文单位、
表格和少见字符存在明显误识别。因此：

- 不从 OCR 语料恢复或比较数学结论；
- 不把 OCR 得到的单个数字当事实；
- 不根据 OCR 的换行判断原文段落；
- 所有会进入写作合同的篇章规律必须经过原页视觉核验或跨论文重复出现；
- 语料只是“真实人类竞赛写作”的样本，不是模型正确性、奖项等级或引用质量的 Oracle。

### 语料观察

以下统计只用于推翻不合理禁令和确定审查方向，不作为机械阈值：

- 17 篇摘要的可识别汉字中位数约 798，范围约 589--1229；摘要数字 token 中位数约 18。
  这说明样本摘要普遍重视具体结果，但不能覆盖当前赛事明确规定的 400--600 字要求。
- `本文` 出现在 16 篇中，共约 87 次；`我们` 出现在 12 篇中，共约 471 次。优秀表达不能靠
  禁止第一人称或强制被动语态获得。
- `首先` 出现在 16 篇中，共约 97 次；`然后` 约 63 次，`最后` 约 60 次。顺序词在真实算法、
  数据处理和分阶段推导中是正常工具，问题在于顺序是否对应真实依赖。
- `建立`、`得到`、`通过` 分别约出现 365、359、247 次，且覆盖全部论文。它们是正常的
  研究动作词；只有缺少明确对象、方法或结果时才构成空话。
- `可知`、`可以看出`、`说明`、`表明` 分别约出现 104、46、100、38 次。图表解释不应禁用
  这些词，而应检查其前面有什么证据、后面增加了什么判断。
- `值得注意的是` 只约出现 5 次且仅涉及 3 篇；`不难发现`、`具有重要意义`、`具有良好的`
  在 OCR 文本中没有精确命中。这支持继续警惕无证据抬价，但不能把字符串零出现当成禁词依据。
- 各篇可识别句长均值约 39--68 个汉字，句长变异系数约 0.69--1.83。长短变化来自公式解释、
  条件和结果密度，不能把随机拆句或追求某个变异系数作为“人味”。

### 可吸收的稳定特点

#### 摘要按问题交付信息

样本摘要通常先用很短的篇幅交代研究对象，随后逐个问题写清使用的模型或算法，并在同一问题
附近给出数值、策略或关系结论。第二版应采用以下正向合同：

- 背景只保留理解题目所需的内容；
- 每个顶层问题至少出现一个可识别方法和一个核心结果或完成状态；
- 方法名必须对应实际 implementation，结果必须来自结构化结果；
- 问题之间用题号、任务对象或真实依赖定位，不为句式变化隐去题号；
- 摘要最后一句只写综合结论或适用边界，不写“最后给出了优缺点”等目录性尾句；
- 篇幅服从当前竞赛规则，不照搬 2019 样本长度。

#### 问题分析完成“题目到模型”的翻译

视觉核验页面表明，较有价值的问题分析会指出决策变量、环境变量、已知边界、目标函数口径、
子系统关系和求解难点，再解释为何需要某类方程、回归或模拟。第二版应要求：

- 不复述题面段落，而是说明题目要求迫使模型具备哪些变量、状态、约束和输出；
- 方法选择附近写出任务需要和适用理由，不只罗列算法名；
- 数据题说明异常、缺失、对齐和比较口径为什么影响后续结论；
- 物理题说明守恒、受力、边界条件和简化假设如何进入 formulation；
- `对于问题一`、`针对问题二` 是合法定位语，不因重复题号本身报警。

#### 模型章节局部闭环

样本常用“建模目的或物理关系—变量/公式—关键项解释—离散或求解办法—结果”的局部结构。
第二版应检查每个主要公式附近是否形成这条闭环，而不是要求所有公式后固定写若干行：

- 公式前说明它回答什么问题或连接什么量；
- 公式后只解释关键项、边界条件、量纲或实现方式，不逐字符翻译；
- 术语和符号稳定复用，不为避免重复创造近义名称；
- 假设、符号和真实算法步骤允许使用列表；连续论证仍使用段落；
- `建立`、`构建`、`求得`、`得到` 后必须出现明确对象或结果。

#### 结果解释形成证据链

原页中较完整的图表分析先定位图表中的具体差异，再用模型关系解释原因，最后说明策略选择或
适用范围。第二版采用四步证据链，实际内容简单时可以合并，不强制四句话：

1. **证据定位**：指出图、表、结构化指标或方案比较对象。
2. **可核观察**：报告方向、数值、区间、残差、稳定状态或约束激活情况。
3. **机制解释**：用模型变量、方程或数据条件解释为何出现该现象。
4. **决策与边界**：说明该结果支持什么选择，以及只在哪些条件下成立。

`由图可知`、`可以看出`、`表明` 和 `说明` 不是错误。只复述坐标轴，或从图形直接跳到“模型
成功”“现实意义重大”，才需要修改。

#### 模型评价必须具体

语料中的评价章节质量差异明显，不能整体模仿。可吸收的写法会指出某个建模选择带来的能力，
以及某项假设、数据分辨率或缺失机制造成的影响。例如，短管均匀密度假设不能直接外推到长管，
日均数据会损失小时级变化，完全弹性碰撞会带来系统误差。第二版要求：

- 优点写成“设计选择—获得的能力—已有证据”，不写形容词清单；
- 局限写成“缺失机制或数据—可能偏差—受影响结论”，不写礼貌性自我批评；
- 推广写清变量映射、需要新增的数据和必须重校准的参数；
- `简便易行`、`结果可靠`、`可操作性强`、`推广面大` 等无证据表述仍应报警；
- 语料中引用质量、模型正确性或不严谨结论不得被语言 Skill 继承。

### 不吸收的表面特点

- 不照抄题号开头、固定章节标题、长句、第一人称或顺序词频率。
- 不为了像 2019 论文而采用已经过时或不符合当前合同的摘要长度、页数和排版。
- 不学习原文中的错别字、口语化、软件名堆砌、泛化评价和缺少证书的最优性声明。
- 不把“展示论文”自动视为最高奖论文，不依据文件夹代码猜测获奖等级。
- 不从原文提取可识别段落作为 Skill 示例；示例必须自行编写或脱敏重构。
- 不把短语频率训练成 AI 检测器或概率分数。

### 第二版 Skill 行为变更

#### Writer

- 在写每节前加载对应章节合同，并在内部建立“任务—证据—判断—边界”段落账本。
- 摘要按顶层问题检查方法和结果覆盖，不再只检查四要素是否整体出现。
- 问题分析明确决策变量、状态、目标、约束、输出和方法理由。
- 结果段优先生成证据链，禁止补足固定行数。
- 评价与推广使用具体因果结构，不用一组通用优缺点完成所有题目。
- 允许 `本文`、`我们`、顺序词和图表引导词，但同一段连续重复时改写组织，不做同义词替换。

#### Reviewer

语言表达维度新增五项只读检查：

1. 顶层问题在摘要中的方法—结果覆盖。
2. 问题分析是否完成从题目到 formulation 的转换。
3. 主要公式附近是否存在目的、含义和实现闭环。
4. 图表与结果段是否形成证据—观察—解释—边界链。
5. 优点、局限和推广是否具体到模型机制与数据条件。

文风问题默认是 `warning`；若表达掩盖结果失败、改变方法证书、编造数字或使顶层问题看似已完成，
仍按现有数值、方法和完成合同判 `fail`。

#### 确定性审计器

现有审计器第二版应保持“只定位、不自动改文”，并作最小调整：

- `sequence_template` 不能因为一篇文章同时出现“首先、其次、最后”就报警；只有顺序词附近没有
  可识别动作或依赖，或多个章节反复使用同一整套模板时才提醒。
- `repeated_paragraph_opener` 对 `问题一`、`对于问题一`、`针对问题一` 等章节定位语降级；
  同一问题内部连续以相同元话语开段才提醒。
- 保留 `generic_claim`、`nominalization` 和近重复检查，但 `建立/得到/通过` 本身不报警。
- 新增摘要问题覆盖报告：`audit` 可选读取 analyze 完成契约 JSON（`subproblems[].id`、
  `title`、`aliases`、`results`、可选 `method_terms`），按任务、方法、结果三路证据报告，
  不依赖单一中文题号或结果变量名猜测。
- 顺序词、证据窗口、段首和近重复检查按 LaTeX/Markdown 章节边界分别运行；跨章节出现合法
  “首先”不得累计成模板 warning。
- 新增结果证据链线索：含 `可知/表明/说明` 的句子附近缺少图表引用、数值、公式或结构化结果时
  提醒人工判断；有证据也不能自动判定解释正确。
- 新增评价具体性线索：优点或推广只有通用形容词，未出现模型对象、数据条件、参数或适用场景
  时提醒人工判断。
- 不把本轮 17 篇语料的任何频率或句长统计设为 pass/fail 阈值。

### 第二版评测合同

实现阶段在现有 `evals/evals.json` 基础上增加分层评测，但不保存原论文全文：

1. 摘要：覆盖多个顶层问题，检查方法、结果和状态逐题对应。
2. 问题分析：把题面复述改成决策变量、状态、约束、输出和方法理由。
3. 模型说明：保护公式并补齐局部闭环，不逐字符翻译。
4. 结果解释：把机械读图改成证据链，不新增数字。
5. 模型评价：把通用优缺点改成机制、影响和推广条件。

每类至少包含一个应修改样例和一个本来就成立、不得被过度润色的反例。验收同时检查：

- 公式、数值、单位、引用、图表编号和 MMW 追踪信息 100% 保持；
- 不新增结构化结果中不存在的数字或结论；
- 摘要顶层问题的方法—结果覆盖不下降；
- 通用评价、重复总结和无证据抬价减少；
- 合法第一人称、顺序词、图表引导词和真实列表不被机械清除；
- 由人工盲评比较首版与第二版的准确性、信息密度、逻辑清晰度、模板感和学术克制；
- 使用昨天真实交付论文只读回归，不能修改原论文、`.mmw/`、`output/` 或现役版本。

不增加第九个流水线阶段，不引入 OCR 运行依赖，不把外部语料打包进 Windows 发行物。若要建立独立的论文语料库、
训练分类器或微调模型，必须另立规格并获得用户确认。
