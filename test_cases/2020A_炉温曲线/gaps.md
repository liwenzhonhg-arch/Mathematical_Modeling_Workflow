# 缺陷与待改进清单 — 2020A 盲测

## 严重

- [x] **[工具] 代码兼容性错误未在生成前发现**：注入真实依赖版本，当前 NumPy 无 `np.trapz` 时执行前替换为 `np.trapezoid`。
- [x] **[工具] code/solve 失败仍可审批传播**：失败或空结果现在不能审批。
- [x] **[工具] 摘要确认数字无出处仍可审批**：`needs_upstream_data=true` 触发 paper 门禁。
- [x] **[工具] review 明确发现硬约束违规和自相矛盾仍可审批**：checklist fail 会拒绝审批和导出。
- [x] **[工具] 题目要求的 `result.csv` 未生成或校验，export 仍成功**：solve/export 均检查题面确认的硬交付物。

## 中等

- [x] **[工具] EDA 的温区持续时间算法错误或定义不清**：第二轮按两个连续区间积分为 126.5 s，并打印 0.5 s 采样间隔。
- [x] **[提示词] Verifier 对固定变量提出错误修改建议**：验证提示现在要求回看题面，固定变量不得建议改成决策变量。
- [x] **[工具] result.csv 编码识别不稳**：第二轮通过 `gb18030` 成功读取。
- [x] **[工具] solve 图表收集缺少本次运行边界**：只接受本次新增或重写产物。
- [x] **[工具] 外部检索占位语句未落地**：新增 `research_evidence.json`，明确外部检索未执行和待搜索项。

## 轻微

- [x] **[体验] Rich 流式重绘导致日志过大**：非 TTY/重定向时不启用 Live。
- [x] **[体验] 部分 Windows 子进程输出存在编码显示问题**：子进程和日志统一 UTF-8。

## 第 4 轮新增

- [x] **[工具] Coder 生成未定义结果变量**：反思提示要求检查所有读取位置和各执行路径赋值，第 5 轮未复现。
- [x] **[工具] 反思循环未验证修订是否改变根因代码**：相同错误增加升级反思机会并限制到第 3 次停止。

## 第 5 轮新增

- [x] **[工具] 超时反思没有降复杂度**：超时专用反思和连续 2 次停止已实现；v3 第二版在限时内完成。
- [x] **[提示词] Coder 缺少计算预算**：提示已要求估算 PDE/优化调用、限制 `maxiter/popsize`、缓存和粗到细搜索。

## 第 6 轮新增

- [x] **[工具] 无可行解时用默认值伪装完成**：运行日志出现“输出占位结果”时 code/solve 均不可审批。
- [ ] **[模型/代码] 热传导模型校准和可行域仍不可信**：v3 的 `R²=0.2544`，问题 2～4 没有可信可行解；需回到 model/code 修订，而不是继续论文阶段。

## 第 7 轮新增

- [x] **[工具] code 重跑丢失上一版失败证据**：复用上一版代码、运行日志和门禁错误定向修订。
- [x] **[工具] 只识别“占位结果”而漏过罚函数/无可行解**：新增罚函数值和无可行解门禁，v4/v5 均被阻断。
- [x] **[工具] code 反复失败不能回传 model**：显式重跑 model 时读取最新 code 门禁证据并进入现有 Modeler/Verifier 修订闭环。
- [x] **[模型] v7 仍缺关键物理定义**：切换 V4 Pro 后从 v7 定向修订到 v12，控制方程、Robin 边界、入口/出口环境温度、等效长度和量纲均通过 Verifier；v12 仍有参数可辨识性 warning，暂未自动审批。

## 第 8 轮新增

- [x] **[工具] 摘要达到 85 分但超过 600 字仍提前停止**：停止条件同时检查评分和正文长度；超长摘要定向压缩到 520～550 字并重新评分。
- [x] **[工具] 优化失败后借用其他子问题解仍可审批**：识别“使用替代/参考解”“无法完成子问题”“无可行或近似解”和“违反约束近似最优”等明确失败输出。
- [x] **[工具] model 激活版本变化后仍反思旧模型代码**：仅复用由当前激活 model 生成的 code 检查点。
- [x] **[工具] DeepSeek 流式响应读取超时穿透重试层**：`httpx.TimeoutException` 和 `httpx.NetworkError` 纳入公共流式重试。
- [x] **[工具] 代码被截断且没有主流程，空 stdout/stderr 仍判成功**：空运行日志现在触发 code 门禁。
- [ ] **[模型/代码] v17 Verifier pass 但真实仿真仍无可行解**：code v15 的最小惩罚解同时违反峰值、升温斜率和温区持续时间约束；需要人工建立基准实现或引入已验证的 2020A 方程/参考结果做回归测试，不能继续依赖 LLM 自证模型正确。

## 第 9 轮新增

- [x] **[工具] 2020A 缺少独立于 LLM 的确定性回归标准**：新增公开代码移植基线、交叉范围契约，以及 code/solve 可选参考门禁。
- [x] **[工具] 本次代码未写 results.json 时可能读取旧结果通过参考校验**：记录执行前文件签名，只接受本次新建或重写的结果预览。
- [x] **[工具] 损坏的参考契约会被静默忽略**：存在但超限、不可解析或 schema 非法时直接阻断 code。
- [ ] **[模型/代码] 当前生成模型仍未达到公开基线**：code v16 的温区 8 结束温度和问题二速度越界，且问题二近似解违反升温斜率与 150～190°C 持续时间约束；下一轮应基于 `reference_solver.py` 的位置相关换热结构重建模型，而不是继续调惩罚权重。

## 第 10 轮新增

- [x] **[工具] 参考答案进入 Coder 提示词造成评测污染**：Oracle 已移出正常流水线，只能由独立 benchmark 在生成结束后读取。

- [x] **[工具] “约束满足: False”和“无可行解后使用替代”未阻断 code**：新增运行日志门禁，r1 回放后 code/solve 均失败。
- [x] **[工具] code 失败日志丢失 stdout 诊断**：失败检查点和反思现在同时保留 stdout/stderr，r2 的 R²、RMSE 和最接近候选可直接定位。
- [x] **[提示词] Coder 看不到题目原文导致遗漏指定点值**：传入不可信标记下的题面原文，只提取任务要求，不传 Oracle。
- [x] **[提示词] 无参数证据仍断言 Bi<0.1 并采用集总模型**：Modeler/Verifier 增加简化可证性和低拟合质量升级要求。
- [ ] **[模型/代码] 仍未得到通过公开基线的全新可行解**：r1 产生违反约束的 60 cm/min，r2 在低质量标定后诚实失败；需要继续改进热传导结构，但不得把 Oracle 数值写回生成提示。
- [x] **[外部] DeepSeek 余额不足阻断最终 r3**：r4 已在新的干净工作区完成有效调用，外部余额不再是当前阻塞。

- [x] **[工具] code 阶段不检查结果 schema 和显式 `可行性=0`**：现在校验本轮新写入的 `results.json`、每项 `name/value/unit/desc` 及验证/约束/可行性状态。
