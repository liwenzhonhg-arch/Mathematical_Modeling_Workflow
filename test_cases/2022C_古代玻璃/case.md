# 案例：2022 国赛 C 题 古代玻璃制品的成分分析与鉴别

- **测试日期**：2026-06-11
- **题目来源**：[Chaydo123/2022-CUMCM-C](https://github.com/Chaydo123/2022-CUMCM-C) 的 C题.pdf 与 附件.xlsx（3 表单：58 件文物信息 / 69 采样点成分 / 8 件待鉴别）
- **题型**：数据分析型（C 类）——统计检验 + 分类 + 聚类 + 关联分析

## 关键数值

- 有效性筛选：69 → 67（剔除 2 行成分和超出 85%~105%，与官方讲评一致）
- 决策树 5 折交叉验证准确率 0.8692
- 风化与纹饰关联 p=4.7e-05（显著）；风化与类型 p=0.247（不显著——与部分参考论文结论不同，见 gaps）

## 本次实测触发的工具修复（已落地进 mmw 代码）

1. **EDA 架构重构**（最大收获）：旧设计只给 LLM 文件名+大小、生成的代码从不执行 → 新流程「pandas 真实结构摘要 → 生成代码 → 沙箱执行（败则修 2 轮）→ 只按真实 stdout 写报告」，报告产出 eda_output.txt 留底
2. **coder 防伪造数据**：stage_code 传真实 data/raw 文件清单进提示词；coder.j2 规则 12 + code.j2 + reflection 三处铁律「严禁模拟数据，读不到就 raise」
3. **coder 切大输出模型**：deepseek-chat 8192 上限装不下 C 类题单文件代码（27KB+），结构性结论：C 类题 coder 必须用大输出模型
4. **摘要评分解析韧性**：JSON 候选提取（原文 → 首尾大括号切片），失败时保留 raw_response 便于排查
5. **LaTeX 图片路径 + PDF 完整性校验**：`\graphicspath{{figures/}{./}}` 解决裸文件名引用崩溃；compile 成功判定从「文件存在」升级为「尾部含 %%EOF」（首跑产出 8.8KB 损坏 PDF 却报成功）

## 结论

C 类题把 B 类题没暴露的问题全逼出来了：EDA 真实性、代码量上限、伪造数据兜底、JSON 解析韧性。四个修复全部落地后，流水线对数据类题目的可信度从「不可用」提升到「可用但需人工把关数据关联」。
