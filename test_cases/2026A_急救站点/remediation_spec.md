# A 题完整性修复规格

## 目标

把本地测试题 `A题.docx` 从“八阶段均可审批但只完成静态代理”修到：

1. DOCX 正文中的结构化表格进入数据探索和后续数据血缘。
2. 三个问题都有可执行、可复算、可解释的数值结果。
3. 问题二纳入 45 分钟任务占用、逐车可用状态、排队、跨站支援和每日 12 次上限。
4. 问题三给出明确事故时长与强度情景、外援车辆配置、动态仿真结果及效果对照。
5. 区域中心点假设具有空间扰动敏感性结果，不再只做车速和准备时间扰动。
6. 论文包含独立的“问题分析”，关键数字均可追溯到结构化结果，元数据不冒充正式队号。
7. PDF 编译日志没有 LaTeX 错误、未定义引用、`Float too large`，也没有超过阈值的版面溢出。
8. 提交包包含论文、代码、当前图表、`results.json`、`sensitivity.json` 和题目要求的硬交付物。

## 已确认的失败证据

- `02_eda/v1/data_summary.md` 把题目判为“无数据”，但 DOCX 内有地区、候选站点和参数三张表。
- `05_code/v8/solution.py` 的问题二只计算无等待静态首程；45 分钟任务时长没有进入车辆占用状态。
- 问题三只给出 24 小时容量下界，没有事故持续时间、动态派遣过程和方案效果对照。
- 中心点模型的空间扰动实验显示黄金时间覆盖对点位假设敏感，原论文却没有报告该敏感性。
- 最终 PDF 标题为文件夹名 `mmw-test`，测试队号为 `TEST-RUN`，缺独立“问题分析”章节。
- 编译日志包含 `Float too large for page`，符号表与页脚发生视觉重叠。
- review 在最终编译前完成，编译器只拦截硬错误和页数，没有把严重版式警告视为失败。
- `submission.zip` 没有打包 `results.json` 与 `sensitivity.json`。

## 根因

1. **输入分类错误**：`ProjectPaths.data_files()` 只返回附件，EDA 不读取主 DOCX 中的表格。
2. **完成度门禁过弱**：solve 只检查每个 `qN_` 至少出现一个结果名，无法判断题目要求的方法和方案是否真正实现。
3. **提示边界混淆**：Reviewer 被允许接受“诚实说明的代理”，但系统没有把“结果可信边界”和“题目完成度”分成两项检查。
4. **验证顺序错误**：review 发生在 compile 之前，最终 PDF 的排版问题不在评审证据中。
5. **编译判定过窄**：只要 PDF 有 EOF 且无硬错误就成功，严重浮动体和盒子溢出不会阻断交付。
6. **导出清单不完整**：导出器只包含 PDF、代码、当前图和题面硬交付物，遗漏结构化支撑结果。

## 情景模型边界

- 题面没有逐次呼叫时刻与车辆轨迹，因此问题二、三使用可复现的有限时间离散事件情景仿真。
- 地区日需求转为 24 小时均匀 Poisson 到达；这是显式情景假设，不是现实观测。
- 单次任务从派遣起占用车辆 45 分钟；响应时间由排队等待、3 分钟准备和行驶时间组成。
- 每辆车每日最多执行 12 次任务；跨站支援和备用阈值必须在代码中具体实现。
- 事故情景必须枚举持续时间与需求倍数，外援到达条件也必须明确；结果只能标为
  `scenario-feasible`，不能宣称现实部署已验证。

## 验收标准

- 公共回归测试全部通过，并增加以下最小回归：
  - DOCX 表格可提取为结构化数据摘要；
  - solve 按 analyze 给出的完成契约拒绝缺项结果；
  - LaTeX 严重版式警告导致编译失败；
  - export 包含结构化结果。
- 新一轮 A 题八阶段均为新激活版本，不能复用第 1 轮代理结果冒充完成。
- `solution.py` 在隔离目录重复运行成功，结构化结果哈希稳定或满足声明的随机种子重复性容差。
- 至少一次独立复算或独立仿真核对核心指标。
- PDF 逐页渲染检查，标题、章节、表格、公式、图片、页眉页脚无已知重叠或截断。
- benchmark 绑定当前 solve/review 版本；无独立 Oracle 时最终等级仍为 `scenario-feasible`。
- 正式参赛队号属于用户输入，测试运行不得伪造；正式导出前必须由用户填写真实队号。
