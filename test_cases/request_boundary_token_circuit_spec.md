# LLM 请求边界 Token 熔断 Spec

状态：**已实现并经真题恢复验证（2026-07-29）**

## 问题

托管控制器只在整个阶段返回后重算检查点 token。2020A r7 设置 `800000`，model
阶段内部继续完成多次 Modeler/Verifier 请求，最终到 `920723` 才暂停，超出
`120723`。因此当前只是阶段边界检查，不是可依赖的预算熔断。

## 规则

1. 每次 OpenAI-compatible 或 Codex CLI 请求取得供应商 usage 后，立即通知当前托管
   运行；不等待阶段保存检查点。
2. 累计达到上限时，本次 usage 先进入调用日志和托管状态，然后抛出专用预算异常，
   阻止同阶段后续 LLM 请求。
3. 使用 `ContextVar` 绑定观察器，避免 GUI 同时运行不同项目时串用预算。
4. 每次调用日志是唯一请求记录，优先按日志求和；检查点版本中的累计 Agent usage
   只能在没有日志时回退使用，禁止把同一 Agent 的累计值跨版本重复相加。
5. 请求观察累计与已落盘日志取较大值，恢复托管沿用同一 run 的真实日志累计。
6. 供应商只在请求结束时返回 usage，因此最多仍可能超出当前单次请求的 token；界面和
   文档必须称“请求边界熔断”，不得称绝对硬上限。
7. 不记录 prompt、原始供应商事件、密钥、账号或 Codex 会话。

## 验收

- 阶段内第一次请求使累计达到上限时，后续代码和第二次请求不再执行。
- 暂停状态保存包含刚完成请求的真实 token，失败原因明确为请求边界预算耗尽。
- 无托管观察器时现有 LLM 调用行为不变。
- r7 的唯一调用日志总和应为 `695020`，不能继续误算为检查点累计和 `920723`。
- 托管、LLM 与全量测试通过。

真实恢复证据：r7 的唯一调用日志先纠正出发累计为 `695020`；恢复后第一项请求把
累计带到 `794666`，第二项请求完成后到 `885632` 并立即触发专用异常，后续
Verifier 请求没有执行。相对 `800000` 的超出量为当前单次请求的 `85632`，不再继续
完成整个 model 阶段。
