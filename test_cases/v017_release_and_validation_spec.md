# v0.1.7 发行与真题复验规格

## 目标

本轮只关闭三个已经被真实运行暴露的问题，不新增顶层阶段或新 Agent：

1. Windows 发行构建不得继承系统 Python 中的无关包。
2. 用一套全新真实题完整运行 `analyze -> review -> export`，实际经过方法试跑门禁。
3. 2010A 在当前代码上执行无缓存冻结复跑，验证累计修复而不是复用旧产物。

## Windows 发行验收

- `build-windows.ps1` 必须创建版本专属隔离虚拟环境，并从仓库内锁定文件安装发行依赖。
- 已存在的构建目录、发行目录、ZIP 或 SHA256 文件仍然拒绝覆盖。
- ZIP 必须包含 `MMW.exe`、`README-Windows.txt`、GUI 静态入口、提示词、知识库索引和移动热模块。
- ZIP 不得包含 `.env`、Git 元数据、工作区、测试用例、缓存或疑似密钥文件。
- 自动校验 ZIP 路径穿越、压缩包大小、解压后总大小、SHA256 文件和 CRC。
- 自动执行冻结版 `MMW.exe -m mmw.cli --help` 冒烟测试；失败则整个构建失败。
- 验收逻辑使用 Python 标准库，并保留最小单元测试，不增加第三方依赖。

## 全新真题验收

- 使用新的工作区名称和空检查点，不复制历史 Agent 产物。
- 不绕过本地门禁或 Verifier；阻断时修复通用代码、提示词或方法契约后重跑。
- 必须保留阶段版本、运行历史、token/时长记录和最终可信等级。
- `code` 阶段存在方法候选合同时，必须留下 `method_pilot.json` 及通过证据。
- 完成条件是论文编译、数值审计、benchmark、PDF 视觉门禁和 export 全部有可核验结果。

## 2010A 冻结复验

- 使用官方题面和附件的新副本初始化，不复用旧检查点、recovery 或 output。
- 记录本次代码提交、模型配置、token/时长预算和每个阶段激活版本。
- 至少完成一轮无缓存全流程；若时间和预算允许，再执行第二轮验证重复性。
- 只有 benchmark、数值审计、PDF 视觉质量和 export 同时通过，才标记本轮完成。

## 非目标

- 不增加视觉模型、文献全文下载、GUI 新页面或新的 Agent。
- 不把缺少外部实验数据包装成代码缺陷。
- 不把有限候选搜索改写为全局最优证明。
